# PC定型業務ゼロ化プロジェクト

企画書 v2.0（業務改革・AI活用・人材育成の3本柱）と初回アンケート設計書の内容を、1つのWebアプリにまとめたものです。企画書と設計書の本文は `企画書・設計書.md` にあります。
Python / Flask / SQLite で動き、サーバー1台（または担当者のPC）で社内に公開できます。

> なくすのは作業。増やすのは人の可能性。

### 大事にしている原則

受けた案件をそのまま自動化しない。その仕事のアウトプットを確認し、なぜやるのかを明確にし、
ECRS（排除・結合・入替・簡素化）の観点でムリ・ムダ・ムラを取り除いて業務プロセスを最適化したうえで自動化する。
案件詳細の「標準手順」と「ECRSの検討メモ」はこの順序で進めるように作ってあります。

### 画面の説明は吹き出しで

画面の説明・凡例・注記・数え方の説明は、見出しや項目の横の ⓘ にまとめ、画面には出しません。ⓘ にマウスを1秒ほど置くと吹き出しで出ます（キーボードでは Tab で ⓘ に移ると出ます）。テンプレートでは `{{ C.tip("説明") }}` で置き、`app.js` が `data-tip` を持つ要素に吹き出し（Bootstrap の Tooltip、表示まで1秒）を付けます。回答者が使う画面（月次アンケート・自動化アイテム登録・活動状況）の最初の案内や、答えるのに要る指示、エラー・注意・空の表示は、画面に出したままにします。

## 動かし方

必要なもの: Python 3.9 以上

```bash
pip install Flask Flask-SQLAlchemy waitress
```

```bash
flask --app app run --host 0.0.0.0 --port 5000
```

ブラウザで http://localhost:5000 を開きます。同じネットワークの他のPCからは `http://<このPCのIPアドレス>:5000` でアクセスできます。

- ポートは `--port` で変えます（例: `--port 8080`）。`--host 0.0.0.0` を付けないと同じPCからしか開けません。
- `--app app` は `run` より前に書きます（`flask run --app app` はエラーになります）。`flask` コマンドが見つからないときは `python -m flask --app app run --host 0.0.0.0 --port 5000` と書きます。
- `python app.py` でも起動できます。こちらはポートを `config.py` の `PORT` から読みます。

`flask run` と `python app.py` は開発用サーバーです。部署に公開して常時動かすときは waitress で起動します。

```bash
waitress-serve --host 0.0.0.0 --port 5000 --call app:create_app
```

- 同時アクセスに強く、開発用サーバーの警告も出ません。ポートは `--port`、処理スレッド数は `--threads`（既定 4）で変えられます。
- `python app.py serve` でも同じことができます。こちらはポートとスレッド数を `config.py` の `PORT` と `THREADS`（既定 8）から読みます。
- Windows のタスクスケジューラに「ログオン時に `waitress-serve --host 0.0.0.0 --port 5000 --call app:create_app` を実行（開始フォルダはこのフォルダ）」と登録しておくと、PCを再起動しても自動で立ち上がります。

### テスト

```bash
python tests.py
```

`tests.py` に7本のスモークテストが入っていて、画面と API をひととおり叩きます。一時ファイルの SQLite を使うので `instance/` のデータには触れません。1本だけ動かすときは `python tests.py smoke_board` のように名前を指定します。

- 初回起動時に `instance/portal.sqlite3` が作られ、Gr・役割・業務領域のマスタと設定の初期値が入ります。既存DBへの列追加は起動時に自動で行います。
- 「管理」→「デモデータを投入」で、回答者8人・業務26件・社員12人（ユーザーID DEMO-001〜DEMO-012、氏名は架空）・月次アンケート4か月分の架空データが入ります。業務は本番の登録と同じく手順（聞き取り）から作り、AI を使わないルールで項目を埋めます。デモデータがある間は、公開の活動状況を含む全ページに「デモデータを表示中」の帯が出て、改善案件の一覧・ダッシュボードの最近の業務にはデモの印が付きます。動きを確認したら「デモデータを削除」で消せます。デモが作ったGr・役割・業務領域・月次の設問セットも、ほかで使われていなければ一緒に消えます。デモのユーザーIDで本物の業務を登録していた場合は、その人と業務を残し（デモの印を外す）、入れ直しても同じIDの人を使い回します。残した人は削除のときにユーザーID・氏名・件数つきで知らせ、人財一覧のその行に「デモのユーザーIDで本物の業務あり」（月次の回答だけなら「…本物の回答あり」）の印を付けます（回答率に入れないときは対象外にします）。デモの業務のうち「日報の実績をExcelの集計表に転記する」には見本の改善案（改善後の流れ・削減見込み）を付けてあり、案件詳細では「デモ」の印を付けて、AI で分析したものではないことが分かるようにしています。
- 設定はすべてプロジェクト直下の `config.py` に書きます（環境変数や .env は使いません）。ポートは `PORT`（`python app.py` / `python app.py serve` のとき。`flask run` と `waitress-serve` では `--port` で指定）、管理者アカウントは `ADMIN_ID` / `ADMIN_PASSWORD`、ユーザーID照会は `LDAP_API_*`、AI連携の推論量などは `OPENAI_REASONING_EFFORT` などです（URL・API キー・モデル名は管理画面で設定）。変えたら再起動します。

## 業務マップ（1枚の流れ図）

登録された業務から、仕事と情報の流れを1枚の図に自動生成します。案件が増えるほど全体像が描かれていきます。図の決まりごと（前提）は `企画書・設計書.md` の「13. 業務マップの前提」にまとめています。

### 図の決まりごと（箱は2種類、線は2種類）

| 要素 | 意味 | 付いている情報 |
| --- | --- | --- |
| 作業の箱（四角） | だれかがやる作業。登録済みの業務、前後の業務、渡す相手の作業 | だれ（職場内・上司・他部署・社外・システム・不明）。「製造1課 課長」のように太字で書く |
| 情報の箱（書類・円柱・角丸） | 作業が使う情報・作る情報 | 媒体（Excel・紙・システムのデータ・メール本文・口頭など）。形とアイコンで表す |
| 仕事の流れ（太い灰の矢印） | 作業 → 作業 | 引き継ぎ方（前が伝えに行く／後ろが取りに行く） |
| 情報の流れ（細い青の矢印） | 作業 ↔ 情報 | 方法（メール・PHS・電話・会議・手渡し・共有フォルダ・システムなど） |

- 情報どうしを結ぶ線はありません。点線は「名前から推定したつながり」です（業務マップから書き戻した業務どうしのつながりは実線）。
- だれ・媒体・方法・引き継ぎ方は、名前や動詞の語から判定します。判定に使う語は 管理 →「業務マップの区分」で変えられます（行の追加・並べ替え・除く語・お試し判定。上の行から先に当てはめます）。情報の流れの方法にもアイコンを選べ（「なし」も選べる。既定は PHS＝携帯電話、電話＝受話器、メール＝封筒、チャット＝吹き出し、FAX＝プリンター、会議・朝礼＝人々、掲示＝イーゼル、手渡し＝歩く人、共有フォルダ＝フォルダ、システム＝データベース、口頭＝かぎかっこの吹き出し、その他＝なし）、線のラベルでは方法の名前の前にアイコンを出します（一覧の図・案件の流れ図・編集画面とも。図の凡例の「方法」に、図に出ているアイコンと名前を並べます）。
- 氏名は図に出しません。「〇〇さん」や社員名簿の氏名は「担当者」（だれ未確認）、「佐藤課長」は「課長」に置き換えます。「営業さん」「お客様」のような部署・相手の呼び方はそのままです。月次アンケートで挙がった業務名、編集画面で書いた箱の名前・だれ・線のラベル（だれの区分を手で選んでいても）、業務データに書き戻す値も、サーバーで同じように置き換えます。
- 色は役割です。登録済みの業務（青）、完了した業務（緑）、保留中の業務（青の点線の枠に「（保留）」）、廃止した業務（薄い灰に「（廃止済み）」。決定が「廃止」で完了した案件）、他の人・部署の作業（白）、未登録の業務（灰の点線）、使う人が分からない（赤）、取り出し元の情報（黄）、できるもの（白・青枠）、同じできるもの＝統合候補（橙）。凡例には図に出てくるものだけを並べます。

| 形 | 媒体（既定の区分） |
| --- | --- |
| 書類（下が波） | Excel・Word・PowerPoint・PDF・CSV・紙・帳票・写真・その他の書類 |
| 円柱 | システムのデータ（設備モニタ・画面・端末・表示器なども） |
| 角丸 | Web、メール本文、チャット、口頭、掲示・ホワイトボード |

- 「設備モニタ」「モニター」「画面」「端末」のような名前は、システムのデータ（円柱・システムのアイコン）として描き、図の下のシステム・情報源の表でもシステムの行に数えます（「自動化アイテム登録」の入力元の分類と同じ）。既定の区分の語に入れてあるので、管理画面で区分を保存したことがある場合は、その語のまま変わりません（「既定に戻す」か、システムのデータの行に語を足すと同じになります）。

| 図 | 描くもの | 元になる設問 |

| 業務マップ | 取り出し元の情報 → 業務 → できるもの → 渡す相手の作業。Gr・役割ごとの枠に業務を置き、前後の業務やできるものの受け渡しをつなぐ。図の下に「システム・情報源と業務のつながり」「Gr・役割・部署の間の受け渡し」の表 | B4〜B7、B17、B18 と「自動化アイテム登録」の聞き取り |
| 案件の流れ図（案件詳細・聞き取り中） | 手順ごとの作業と、その手順が使う・作る情報、渡す相手の作業、前後の業務 | 聞き取りの手順（何をするか・使うもの・できるもの・渡す相手・渡し方・使いみち・受け取り方） |

- Gr・役割・業務領域で絞り込めます（プルダウンを切り替えた時点で図を描き直します。表示ボタンはありません）。1枚の図は業務80件までで、超える場合は絞り込みを促します。
- 箱は「自動化アイテム登録」の聞き取りで答えた**名前**（システム・帳票・部署）で描き、同じ名前は1つの箱にまとめます。1つの手順の「使うシステム」に「、」で並べた取り出し元（例: 「PMK、ライン管理」）は、1つずつ別の箱にして、それぞれをその手順につなぎます（聞き取り中の図・案件詳細・業務マップ・図の下の表とも同じ）。それぞれから受け取る情報は線に書きます（例: PMK →「トラブル装置の対応状況／システム（登録・参照）」、ライン管理 →「生産状況／電話」）。AI が本人の答えを読んで、手順ごとに受け取り元ごとの「どこから・何を・どのように」（手順の `receive`）を意味で対応づけて記録し、図と手順の一覧（「［PMK：トラブル装置の対応状況、ライン管理：生産状況］」）はそれをもとに描きます。`receive` のない以前の登録は、手順の文の「〇〇から△△」から読みます。手順の中で作っている途中のファイルや、同じものの言い換えは取り出し元にしません（業務マップから書き戻した受け取り元は、言い換えとしてまとめずに必ず描きます）。名前が分からず区分（他のExcel・紙の帳票など）しかない業務だけ、「紙の帳票（名前未確認）」のような箱になります。名前のある取り出し元から分類した区分（「設備モニタ」→ 設備データ）は、別の箱にしません。手順のある業務の区分だけの取り出し元は、案件の流れ図と同じく、受け取り方が合う手順（「PHSで聞く」など）があってその手順にまだ取り出し元がないときだけ、その受け取り方で業務の箱につなぎ、ないときは描きません（図の下のシステム・情報源の表も同じ）。「週報・生産管理システム」のような受け取り元は「・」で分けますが、かっこの中の「・」は分けません（「オペレーターの故障連絡（口頭・メモ）」は1つ）。
- ある業務のできるものを、別の業務が取り出し元にしていれば、点線で自動につなぎます（名前が完全に一致するか、「日次実績集計表（Excel）」と「日次実績集計表」のように媒体の書き添えだけが違うとき）。
- 渡す相手は相手の作業の箱（だれ＋使いみち）になります。役職は「製造1課 課長」のようにGr・役割名つき、別のGr・役割の相手はそのGr・役割の枠に置きます。相手の箱は業務ごとで、ID は業務と答えた名前（区分しか分からない相手は区分）で決まるので、区分の語・目的・相手の数を変えても手修正が残ります。1つの業務の中では、だれ（Gr・役割名つきの名前）が同じ相手だけ1つにまとめます（「課長」と「製造1課 課長」は同じ、「検査・品質保証課 課長」は別）。
- 管理でGr・役割名を変えても、前の名前で書かれた渡す相手・前後の業務・受け取り元は、そのGr・役割の枠とだれ（いまのGr・役割名）で描きます。前の名前は `settings` に控え、同じ名前のいまのGr・役割があればそちらを優先します。Gr・役割名（いまの名前・前の名前・「検査・品質保証課」の「・」の後ろの「品質保証課」）は、前後に字が続いていてもそのGr・役割とみなし（「組立課長」「組立課 課長」「組立課向け」「組立課様」「組立課宛」「組立課用」「組立課内」「組立課全体」「組立課二係」、部・本部・工場・事業所・センターなどの組織名が前に付く「製造部組立課」は組立課）、前の名前はいまの名前に直します。そのGr・役割とみなさないのは、前に「第二」「第2」「第一」のような番号や英数字が付いて別のGr・役割になるとき（「第二組立課」は組立課の枠に入れず、組立課を組立1課に変えても「第二組立1課」にしない）と、名前の最後の字と後ろの字で別の言葉になるとき（課題・課程・課金・課税・部品・部分・部位・部材・室温。「組立課題」は組立課と読まない）、英数字で終わる名前の後ろに英数字が続くとき（「ライン1」と「ライン10」）だけです。
- 手順で入力・登録しているシステムには、手順からシステムへ矢印を引きます。メール・PHS などの渡し方は線のラベルに「アイコン＋名前」で書き、媒体から分かる方法（システムのデータをシステムで見る、など）は省きます。
- 案件の流れ図には、手順に出てこない取り出し元・渡す相手（アンケートで答えたもの・業務マップから書き戻したもの）も足し、手順の箱と同じもの（同じ名前、かっこの書き添えだけ違うものなど）はその箱にまとめます。区分しか分からない取り出し元（「人から聞く内容（名前未確認）」など）は、受け取り方が合う手順（「PHSで聞く」など）につなぎ、合う手順がないときや、その手順にもう取り出し元の箱があるときは描きません（業務マップ全体とシステム・情報源の表も同じ決まりで描くか決めます）。手順が書き込むファイルとできるもの（「Excel（日次実績集計表）」と「日次実績集計表」のように、かっこの書き添えだけ違うもの）は1つの箱にします。前後の業務は「、」・改行ごとに1業務1つの箱で、登録済みの業務ならその業務のGr・役割をだれにし、引き継ぎ方は業務マップと同じ決まり（同じ回答者なら引き継ぎなし）です。ほかの業務が前後の業務にこの業務を書いていれば、業務マップと同じくその業務の箱を点線（書き戻したつながりは実線）でつなぎます。箱の色も業務マップと同じで、完了・保留中・廃止済みの業務は手順の箱をその色で描き、情報の箱は線の向きで決めます（手順が書き込む情報はできるもの）。
- 月次アンケート（1-3・3-2）で挙がったのに、まだ流れを登録していない業務は、Gr・役割の枠に灰色の点線の作業の箱で出ます。各人の最新の回答（6か月以内。人財一覧で対象外にした人は除く）を、その回答のGr・役割ごとに見ます。業務名は1行・「、」ごとに分け（「・」では分けません）、全角・半角と記号をそろえて、同じGr・役割に同じ名前の登録済みの業務（書き戻しで業務名を変えた業務の前の名前と、「自動化アイテム登録」をその月次の業務名から始めて登録した業務も）があれば出しません（「月報の作成」と「週報の作成」は別の業務）。前後の業務の名前が同じ業務とは点線でつなぎます。業務領域で絞ったときは出しません。
- 保留中の案件は点線の枠に「（保留）」、決定が「廃止」で完了した案件は薄い色に「（廃止済み）」を付けて描きます（業務マップ・案件の流れ図とも。業務名そのものは変えません）。
- 図の下の表（システム・情報源と業務のつながり、Gr・役割・部署の間の受け渡し）は業務マップと同じ関数で数えます（受け取り元は1つずつ、役職はGr・役割名つき、「他部署」だけの相手は目的の文の部署名）。受け渡しの表は人・所属どうしの表で、手順の受け取り元（`receive`）の人・所属も数え、システム・書類・情報は「から」に置きません。人・所属はシステム・情報源の表には入れません。重複入力は入力元ごとに数えます。絞り込みに関係なく全体で数える表（領域別の把握状況・重複・業務のつながり）には「全体」と書きます。見出しは「図に載せた業務 N 件」です（いつも合計と同じになる「入力あり」の括弧は出しません）。
- 受け取り元が人・所属のときの箱は、所属ごとに分けたまま、所属のアイコンと丸い端で描きます（「不明」の書類に見せません。凡例も「だれ」に出します）。線の「受け取るもの」は線に別に持たせ、表示するときに「受け取るもの／方法」と書くので、編集画面で方法を直すとその方法で書きます。押せる箱（業務の箱。案件詳細を開く）だけポインタにします。
- 図は [Mermaid](https://mermaid.js.org/) 記法で生成しています（生成ロジックは `app.py` の「業務マップ」セクション）。業務の箱をクリックすると案件詳細を開きます。
- 「最大表示」で図を画面いっぱいに広げます（閲覧・編集のどちらも。もう一度押すか Esc で戻ります）。閲覧では図全体が収まる大きさに合わせ、戻すと元の倍率に戻ります。

### 流れ図の手修正（この図を編集する）

自動生成が間違っていたら、「✎ この図を編集する」で手で直せます。エディタは自作の mindmap（Flex Diagram）の操作感を流れ図向けに応用したものです（`app.py` 内の `flowedit.js`、画面は `bizmap/edit.html` テンプレート）。

| 操作 | 方法 |
| --- | --- |
| 箱を動かす | ドラッグ（Shift+ドラッグで範囲選択、Shift+クリックで追加選択、複数まとめて移動） |
| 名前を直す | 文字をダブルクリックして編集、Enter で確定 |
| 箱を足す | 「＋作業」「＋情報」、または箱の ➕（つながる箱を追加） |
| 箱の中身 | 箱をクリック → 種類（作業／情報）、だれ（作業）、媒体（情報）。名前を変えると、手で選んでいない項目は判定し直します（だれの名前は、区分を手で選んでいてもサーバーで氏名を置き換えます） |
| 線を引く | 箱の 🔗 を押して相手の箱をクリック。作業どうしは仕事の流れ、作業と情報は情報の流れになります（情報どうしは結べません） |
| 線を直す | 線をクリック → 方法（情報の流れ）・引き継ぎ方（仕事の流れ）、向きの反転、ラベル、削除 |
| 箱を消す | ✕ または Delete キー（自動生成の箱は「非表示」として記録。「非表示を戻す」で復活） |
| 画面 | 空白をドラッグで移動、ホイールで拡大縮小、「全体表示」「自動レイアウト」「最大表示」 |
| 取り消し | Ctrl+Z／Ctrl+Y、保存は Ctrl+S |

保存した手修正は絞り込み（Gr・役割・領域）ごとに `flow_maps` テーブルに残ります。業務・Gr・役割・領域の番号は使い回さないので（番号の最大を `settings` に控え、起動時に手修正が指している番号より大きくそろえる）、消した業務の手修正が新しく登録した業務に付くことはありません。
次に図を開くときや「再生成」を押したときは、最新の登録業務から図を作り直したうえで手修正を重ねます（`app.py` の `merge_graph`）。

- 新しく登録された業務は自動で追加され、右端に置かれます（配置を整えて保存）
- 手で消した箱・線は復活しません（「非表示を戻す」で戻せます）
- 手で足した箱・線、動かした位置、直した名前・ラベル・色・向き、手で選んだだれ・媒体・方法・引き継ぎ方は残ります
- 未登録の業務の箱に引いた手の線は、同じGr・役割に同じ名前の業務が登録されると、その業務の箱につなぎ直します
- 閲覧用の Mermaid 図にも手修正（名前・だれ・媒体・色・線・追加・削除）が反映され、「手修正あり」のバッジが付きます。配置は閲覧用の図では使わない（Mermaid が並べる）ので、配置だけを保存したときはバッジを付けません
- 「自動生成に戻す」で手修正をすべて捨てられます

手修正は図のレイヤーに保存されます。エディタの「業務データに反映」を押すと、手修正から業務データに反映できる変更を取り出し、選んだものだけを書き戻せます（`app.py` の `writeback_candidates` / `apply_writeback`）。

| 手修正 | 反映先（業務データ） |
| --- | --- |
| 業務→業務の線を引いた | 前の業務の「後の業務」と、後の業務の「前の業務」に追加。反映したつながりは書き戻した印を `settings` に控え、次の再生成から名前から推定した点線ではなく実線で描く |
| システムの情報→業務の線 | 入力情報にそのシステムを追加 |
| 帳票・ファイルなどの情報→業務の線 | 情報の受け取り元（B18）に追加。書き戻した受け取り元は、同じ媒体の取り出し元があっても言い換えとしてまとめず、業務マップ・案件の流れ図に必ず描く |
| だれのある作業→業務の線 | 関わる人・部署に追加（内容があれば前の業務にも） |
| 未登録の業務↔業務の線 | 前の業務・後の業務に追加（「（2人）」は外す）。線は実線になる |
| 業務・できるもの→だれのある作業の線 | 利用者の名前に追加（だれが確かなときはアウトプットの利用者（B5）の区分にも）。だれの区分を手で選び、名前からはその区分にならないときは「山田製作所（顧客・社外）」のように区分を添えて残す |
| 業務・できるもの→だれのない作業の線 | 後の業務に追加 |
| 業務名を直した | 業務名を変更。ほかの業務の「前の業務」「後の業務」に書いた同じ名前（全角・半角と記号をそろえて同じもの）も新しい名前に直し、古い名前は月次の未登録の業務に出さない。名前の一部だけが同じもの（「部長会議資料の作成」を直したときの「部長会議」など）は自動では直さず、「〇〇の後の業務に書いた『部長会議』を『…』に直す」のように直し方を書いた別の候補にする（初めは選ばれていない） |
| 前後の業務の線（点線）を消した | 「前の業務」「後の業務」からその業務名を外す（線を引いたときと同じ決まりで、名前を含むときも名前の一部のときも。未登録の業務への点線も）。書き戻した印も消す |

反映した変更は次回の再生成から自動で描かれるので、同じ線が手修正と自動の二重になることはありません。反映した相手・受け取り元は同じ自動の箱にまとまり（「課長」は渡す業務のGr・役割名つきでも比べる）、手で引いた線もその箱につながります。業務名の変更と前後の業務の追加を一緒に反映しても、新しい業務名で書き込みます。書き戻す値も氏名を置き換えます。書き戻しで業務情報が変わった案件は、案件詳細で業務情報を直したときと同じく、直した項目の推定の印を外し、前回の分析がルールベースならルールの分析をやり直し、AI の分析なら「業務情報を直す前の AI 分析（日時）」の印を付けて（エディタにも「再分析」で新しくなる件数を出します）、改善チームが手を付けた案件になります。

## 活動状況（製造部全体への公開）

「どのGr・役割の案件が、今どこまで進んでいるか」を一目で見せるページです（ナビの「活動状況」、`/board/`）。説明文や集計は置かず、1案件＝「登録元」「業務名（とひとこと）」「7段階のステッパー」の1行だけで構成しています。スマホ幅ではラベルを現在の段階だけにして、横スクロールなしで収まります。

| 段階 | やること | 対応する標準手順 |
| --- | --- | --- |
| 1. 開始 | 検討の登録を受け付け、活動状況に載せる（業務を登録した時点） | － |
| 2. 要求定義 | 何に困っていて、何を実現したいかを本人と整理する | 手順1・2（アウトプットの確認・目的の明確化） |
| 3. 要件定義 | ECRS で業務を最適化し、残る作業の仕様を決める | 手順3（ECRSによる最適化） |
| 4. 作成（伴走） | ツール・仕組みを作る。担当区分が「自主改善」の案件は改善チームが伴走するので「伴走」と表示 | 手順4・5（自動化・高度化） |
| 5. テスト | 実際のデータで動作と効果を確かめる | － |
| 6. 確認 | 本人・Gr・役割で結果を確認し、運用に乗せる | － |
| 7. 完了！ | 運用開始。改善前後の結果を記録する | － |

- 段階の更新は案件詳細の「進捗」カード（◀ 戻す／次の段階へ ▶）で行います。「活動状況のひとこと」に今の状況・次の予定を書くと活動状況に出ます。
- ステータス（受付・対応中・完了）は段階から自動で決まります。開始＝受付、要求定義〜確認＝対応中、完了！＝完了。「保留にする」ボタンで段階を保ったまま保留にでき、段階を動かすと解除されます。
- 段階が変わるたびに履歴（日付）が残り、活動状況の各段階の下と「最近の動き」に表示されます。
- 活動状況の上部には、検討したくなる材料として、年間削減工数と削減率と、直近に完了した2件の改善前後と結果メモを1行に並べています（件数は見出しの帯と「全 N 件」に出すので、累計改善案件のカードは置きません。中身がないときはこの欄を出しません）。完了の一覧は新しい8件を出し、それより多いときは見出しに「新しい 8 件を表示」と添えます。行そのものは押せないので、マウスを乗せても浮かせません。見出しの右には「自動化アイテムを登録する」「月次アンケートに答える」への導線を置いています。数字はダッシュボードと同じ計算で、見出しのプルダウンでGr・役割を選ぶとそのGr・役割の業務だけの値になります。
- 管理 → プロジェクト設定で「登録者の氏名を表示するか」を変えられます（外すとGr・役割名のみ）。

## ログイン（推進メンバー向け）

アンケートの回答（「自動化アイテム登録」・月次）と活動状況はログイン不要で全員が使えます。ダッシュボード・改善案件・業務マップ・月次集計・人財一覧・管理は、ログインした推進メンバーだけが使えます。

- 管理者アカウントは1つで、既定は ID `admin` ／ パスワード `adminpass` です。本番では `config.py` の `ADMIN_ID` と `ADMIN_PASSWORD` を必ず変更してください。
- ログインしていない人がトップページを開くと活動状況に移ります。
- ログアウトするとセッションを丸ごと消します（同じブラウザで保存していた「自動化アイテム登録」の回答者も残りません）。
- ログイン中は、ヘッダーの一般向けタブ（活動状況・「自動化アイテム登録」・月次アンケート）の右に仕切りと 🔒 を挟んで、管理者用タブ（ダッシュボード・改善案件一覧・業務マップ・月次集計・人財一覧・CSV出力・管理）が藍色で並びます。右上の「管理者メニュー」がログインの入口です。
- 画面は横幅いっぱいに使います（左右の余白は画面幅に合わせて 16〜40px。月次アンケートは読みやすさのため 1040px まで、「自動化アイテム登録」は広い画面で流れ図の欄を広く取ります。狭い画面ではメニューが折りたたまれ、カードは縦に積まれ、表は枠内スクロール）。

## 月次アンケート（月度ごとの設問セット）

- 設問は月度ごとの「設問セット」です。推進メンバーは「月次集計 → 設問を編集」で、来月以降の月度の設問を追加・並べ替え・削除できます（前月コピー、基本設問に戻す）。今月と過去の月度の設問は、すでに回答した人のデータと対応が取れなくなるため変えられません（画面は見るだけで、来月の編集へのリンクを出します。保存・削除の要求も断ります）。受付の停止・再開は、今月と前月（回答できる月度）でも切り替えられ、切り替えるとすぐ保存します。月度の一覧では、回答できない古い月度を「終了」と出し、削除できるのは来月以降の設問セットだけです。
- 基本設問（毎月同じ。下表）は KPI の推移に使うため、設問の文面と選択肢の表現だけ変えられます（選択肢の数・順番・意味と必須は固定で、基本設問どうしの並べ替えと削除はできません）。選択肢の表現を変えても、回答は元の選択肢（集計に使う値）で保存するので、推移・KPI・人財一覧・CSV の値はそのまま続きます。回答画面と、月次集計の月度の詳細（分布・回答一覧）はその月度の表現で出し、月をまたぐ推移は元の選択肢で出します。表現を空にすると元の言葉に戻り、ほかの選択肢と同じ言葉（意味が入れ替わる）や重複した表現は保存できません（設問セットの `labels` に保存）。
- 設問エディタは回答画面と同じ番号（1、1-2、2-2 など）を付けます。条件つきの設問は字下げして「1 で「ある」を選んだ人にだけ出します（出たら必須）」と出し、親の設問の選択肢の横に「→ 1-2・1-3・2・3 を出す」と、どの選択肢で何が出るかを示します（表現を変えると、その場で条件の文にも反映します）。回答フォームが初めて開かれた月度は直近の月度からコピーして自動で作られます。設問の編集画面は、開いただけでは月度の設問セットを作らず（直近の月度か基本設問を表示）、保存したときに作ります。
- 回答はログイン不要です。ユーザーIDで本人を特定し（メールのリンクに含まれる）、Gr・役割と勤務形態（普通勤務／交代勤務）は初回だけ選び、〇月度ごとに 1人1回。送信するとその場で「回答済み」になり、再回答はできません。
- 集計（要ログイン）は月度を選んで、設問ごとの分布（人数・%）、記述とコメントの一覧、Gr・役割別、基本設問の時系列グラフを表示します。CSV（CSV出力の「月次アンケートの回答」）は全月度・全設問を横に並べて出力します。

毎月同じ内容のアンケートに回答してもらい、〇月度ごとに集計します。

- 回答ページは `http://<ポータル>/monthly/` です。`?emp=ユーザーID` を付けたリンクならユーザーIDが自動で入ります。同じ月度は1人1回で、2回目は回答済みの表示になります（別のIDで答え直すボタンは置きません。入力の途中で回答済みのIDになったときは設問を隠してIDの欄だけ残すので、打ち間違えたら直せます）。人財一覧で「対象外」にしたユーザーIDは「このユーザーIDは対象外になっています。管理者に連絡してください」と出て回答できません（「自動化アイテム登録」も同じ）。Gr・役割はGr・役割マスタにあるものだけを受け付けます（ないときは「Gr・役割を選んでください」）。
- 集計（`/monthly/results`）は時系列で見る画面です。基本設問の割合の推移グラフと月度別の表、設問ごとの選択肢の割合の推移、Gr・役割別・勤務形態別の推移（PCの定型・定期業務あり率と推計月間時間。勤務形態別には交代勤務の班ごとの行も出す）、月度を選んで見る詳細（追加設問の分布、挙げられた業務、コメント、回答一覧）があります（CSV は CSV出力のタブから。勤務形態つき）。減った・増えた・自動化したいは ① で「ある」と答えた人のうち、依頼したい・一緒に取り組みたい・自分で取り組みたいは「なくしたい業務がある」と答えた人のうちの割合です（その設問に答えた人が分母）。基本設問どうしの順番は固定です（エディタでは並べ替えられず、保存時にも元の順（親の設問が先）にそろえます）。
- 回答率の分母は「人財一覧」の人数です。月次アンケートか「自動化アイテム登録」に一度でも回答した人が、ユーザーIDごとに1行で自動登録されます（重複なし）。各月の分母は、その月までに人財一覧に載った人です（初めて回答した月から。あとから初めて回答しても過去の月の分母は変わりません）。退職・他部門への異動などで外す人は、人財一覧で「対象外」にチェックします。月末時点で「対象外」にチェックしている人は、その月の分母にも分子にも入れません（今月は今のチェックで数えます）。チェックを外すと外した月から分母に戻し、それより前の月は月末時点の状態のまま残します（対象外だった期間は `employees.excluded_spans` に「対象外にした月〜外した月」で控え、いまの対象外は対象外にした日 `excluded_at` から数えます。同じ月のうちにチェックして外したときは、その月は対象のままです）。日付のない以前の対象外は、起動時に更新日（なければ起動した日）を対象外にした日として埋めます。表記ゆれの行をまとめるときも、対象外にした日と対象外だった期間を残します。
- 回答率の隣に出す回答数（月次集計・ダッシュボードの月次カード・人財一覧）は、どれも対象者（対象外を除く）だけで数えます。対象外の人の回答が含まれる月は「回答 N 人（うち対象者 n 人）」と出します。
- 人財一覧は、縦に人、横に1列1つの情報（ユーザーID・氏名・いちばん新しい回答の Gr・役割・勤務形態・班（ユーザーIDを入れたときに呼び出す値と同じ）・技術・自動化アイテムの件数と名前・一緒にやってみたい・伴走・月次の進め方と答えた月と回数・月次で挙げたなくしたい業務と挙げた月など）を並べ、続けて月を並べ、その月に回答した人に ✓、月末時点で対象外の月に「対象外」を付けます（対象者になる前の月は「－」。「対象外」と「－」の月は分母に入りません）。列名を押すと昇順・降順に並べ替え、見出しの下の欄で列ごとに絞り込めます（ユーザーID・氏名・自動化アイテム名・なくしたい業務は文字を含む人、件数・回数は 0／1 以上、ほかは選んだ値。絞り込んだときは、下の「回答 ／ 対象」も表示している人だけで数えます）。前の DX人財情報のアドレス（`/people/?workplace_id=…` など）や次のアクション提案の教育テーマからは、絞り込みを選んだ状態で開きます（`?wish=スキルを身につけながら、一緒にやってみたい` は「一緒にやってみたい（件）」の 1 件以上。`?wish=positive` は絞り込みません）。削除できるのは、まだ月次の回答も自動化アイテムの登録もない人だけです（回答のある人は削除しても次の起動で一覧に戻るため、「対象外」にします）。デモのユーザーID（DEMO-001 など）で本物の業務や回答を入れた人には「デモのユーザーIDで本物の業務あり」の印が付きます。

### 案内の仕方

メール配信の機能はありません。月初に部のメールや掲示で回答ページのURL（`http://<ポータル>/monthly/`）を周知し、本人がユーザーIDを入れて回答します。回答期間（1週間が目安）の間は推進メンバーがGr・役割ごとに声をかけ、月次集計の回答率で進み具合を確認します。

## ユーザーID照会（LDAP 連携）

アンケートの先頭でユーザーIDを入力すると、そのユーザーIDが存在するかだけを照会します（氏名は回答画面に出しません）。照会の順序は次のとおりです。

1. **社内 LDAP API サービス**（HTTP/JSON）: `config.py` の `LDAP_API_URL` を設定。URL に `{id}` を含めると置き換え、含めなければ `?employee_id=<ユーザーID>` を付けて GET します。氏名の項目名は `LDAP_API_FIELD_NAME` で合わせます（`data.name` のような入れ子も可）。Bearer トークンが必要なら `LDAP_API_TOKEN`。照会しただけでは人財一覧に載りません（回答したときに載ります）。
2. **LDAP サーバーへの直接照会**: `pip install ldap3` のうえ `LDAP_SERVER` / `LDAP_BASE_DN` などを設定。
3. **人財一覧**（`employees` テーブル）: 一度でも回答した人。LDAP を使わないときは、ここにあるユーザーIDだけが回答できます（手で追加・CSV 取込する機能はないので、新しい人が回答するには LDAP の設定が要ります。設定の有無は 管理 の「ログインとユーザーIDの照会」に出ます。見つからないときの知らせには、初めて回答する人は改善チームに連絡するよう添えます）。起動時に、表記ゆれだけが違う行は1行にまとめます（どれかが対象外なら対象外のまま）。月次の回答と「自動化アイテム登録」の回答者のユーザーIDも同じ書き方にそろえ（すでに回答で使われている書き方を残します）、同じ人の回答者が2行あれば1行にまとめて業務を移します。同じ月度に表記ゆれで2件ある月次の回答は、先に送られたほうを残し、消した回答は月度・ユーザーID・回答の番号と日時をログに警告として残します（氏名は書きません）。

氏名は `LDAP_API_FIELD_NAME` の項目（例 `display_name`）から取り、なければ `display_name` / `displayName` / `name` / `cn` を順に見ます（人財一覧の表示に使います）。照会で使うのは「いるかどうか」と氏名だけで、「そのIDが存在するか」しか返らない場合でも使えます。Gr・役割と勤務形態は照会では取りません。初めての人は本人がプルダウンで選び、選んだ値は人財一覧（`employees` テーブル）に控えます。一度でも回答した人は、ユーザーIDを入れると前回の回答のGr・役割・勤務形態が入り、「前回の回答のGr・役割と勤務形態を入れました。変わっていたら、今の所属・勤務形態に合わせてプルダウンで選び直してください。」と表示します（すでに選んである値は上書きせず、別のユーザーIDに打ち替えると入れた値を消します）。月次アンケートから「自動化アイテム登録」へ続けて進んだときは、その回答で選んだ値を引き継ぎます。社員マスタを別に用意したり手で保守したりする必要はありません。全角で入力したユーザーIDは半角として扱い、大文字・小文字の違いは同じ人とみなします（月次の回答済みの判定、「自動化アイテム登録」の回答者・月次の答えの呼び出しも同じ）。`config.py` の `LDAP_API_FIELD_EXISTS`（既定 `exists`）が `false` のとき、または HTTP 404 のときは「いない」と判定します。

いずれでも見つからないユーザーIDでは回答できません（「このユーザーIDは見つかりません」と表示します）。

## AI連携（社内 Azure OpenAI の ChatGPT API）の有効化

AI連携は無くても動きます（ルールベースで同じ形式の分析・提案を行います）。社内の Azure OpenAI 中継サービス（ChatGPT API）につなぐと、案件登録時の業務分類・関連業務の推定・ECRS観点の改善候補・担当者への確認質問、およびダッシュボードの「AIで提案を生成」が有効になります。

1. 社内の中継サービスの API キーを用意する（ヘッダーに `Authorization: Bearer <API_KEY>` として送ります。統一IDの入力は不要です）
2. 「管理」画面の「AI連携（ChatGPT API）」に、Responses API の URL（例 `https://openai-api-service.<社内ホスト名>:82/api/responses`）、API キー、使う GPT-6 系のモデル名（社内で案内されている名前）を入力して「保存」する。再起動は不要です
3. 「保存して接続テスト」を押して「接続できました」と出れば成功です。状態表示が「ChatGPT API 連携 有効」になります

URL・API キー・モデル名に既定値はありません。空欄のままなら AI は使わず、ルールベースで同じ形式の分析をします（公式の URL や既定のモデル名に勝手につなぐことはありません）。値は `instance/portal.sqlite3` の settings に保存されます。

呼び出しは Responses API で、本文は `model` / `instructions` / `input` / `max_output_tokens` / `reasoning.effort` だけです。`temperature` と `top_p` は送りません（GPT-5 以降の推論モデルは受け付けないため。0 を入れるのでもなく、項目ごと付けません）。`config.py` で変えられるのは推論の量 `OPENAI_REASONING_EFFORT`（既定 `low`。空にすると送らない。推論なしのモデルで 400 が返ったときは自動で外して1回やり直します）、応答の上限 `OPENAI_MAX_OUTPUT_TOKENS`（既定 4000。推論トークンを含む）、タイムアウト `OPENAI_API_TIMEOUT`（既定 90 秒）です。追加のパッケージは要りません（標準ライブラリの urllib で呼びます）。

失敗したとき（キー無効・URL 違い・レート制限・接続不可・応答の拒否）はログに理由を出し、その案件はルールベースの結果で補います。直近のエラーは「管理」画面の「AI連携」にも出ます。AIの推定は参考情報で、案件詳細の「担当者確認」を経て正式な情報になります。

案件詳細の「AIで再分析」は、登録時と同じ分析（同じ指示と道具。登録済みの内容も渡す）をやり直し、ECRS の観点・改善後の流れの案・削減見込み・業務領域の推定を更新します。書き換えるのは空の項目と、担当者確認の前で推定の印が付いた項目だけで、確認済みの内容や人が直した項目は変えません。AI がないとき（または失敗したとき）は登録時と同じルールで分析し直します。AI 連携が有効なのに使える応答がなくてルールに切り替えたときは、その理由を案件詳細に出します。前回の AI 分析で出た改善後の流れ・削減見込み・ヒアリング質問は消さずに残しますが、「前回の AI 分析（日時）」の印を付けて線で区切り、いまの分析（ルールベース）の結果のようには見せません（CSV の改善後の流れにも同じ印を付けます）。AI で再分析し直すと、いまの分析の案に戻ります。業務情報を直したあとの「業務情報を直す前の AI 分析（日時）」の印も、再分析で消えます。業務領域の名前を管理画面で変えると、案件の AI推定の領域名も新しい名前になり、ルールの推定も（説明文が初期値のままなら）新しい名前で働きます。

## 自動化アイテム登録（AI の聞き取りでフローを作る）

本人がフォームを埋めるのではなく、AI が1問ずつ聞きながら業務の流れを組み立てます。

- 「基本情報」はユーザーID（存在の確認だけ）と、Gr・役割・勤務形態（普通勤務／交代勤務）のプルダウンです。交代勤務を選んだ人だけ班（1班・2班・3班）の欄が出て、選ばないと保存できません（班は `SHIFT_TEAMS`。普通勤務の人の班は保存しません）。Gr・役割・勤務形態・班は、一度でも回答した人ならユーザーIDを入れたときに前回の回答の値が入り、変わっていたら選び直すよう案内が出ます（初めての人は本人が選びます。月次アンケートから来たときは、その回答で選んだ値が入っています。前の月度にあとから答えた回答から来たときは、いまのGr・役割・勤務形態が入ります）。画面は開くたびに空で始まり、前に使った人の内容は出ません。次に「どの業務を検討しますか」で、月次アンケートで挙げた業務名（1-3・3-2。月次から引き継いだ回答があればその回答、なければ直近の回答）がチップで出るので1タップで始められます。業務名は業務マップと同じく1行・「、」ごとに分け（「・」では分けません）、氏名は「担当者」に置き換えて出します（完了ページ・送信後の画面・引き継ぎの帯も同じ）。業務名が決まっていなくても始められます。
- 保存したあとにユーザーIDを別の人のものに打ち替えたり、見つからないユーザーIDにしたりすると、それまでの人の登録一覧・候補とGr・役割・勤務形態を消し、選び直してもらいます（前の人のGr・役割が次の人に付くことはありません）。聞き取り・登録は画面のユーザーIDを一緒に送り、保存した人と違えば（別のタブで別の人を保存したときなど）「画面のユーザーIDと登録先の人が違います。『基本情報』を入れ直してください」と止めます（API は 409）。画面を開いたまま対象外にされた人も、聞き取り・登録は対象外のメッセージで止まります（API は 400）。画面の下の大きなボタンは段階で変わります。業務名を入れる段階では「聞き取りを始める」（業務名の欄の見出しは「業務名」）、聞き取り中と登録の入力中は出さず、この画面で業務を登録したあとは「送信して完了」も出します（登録した直後は「送信して完了」が主なボタン）。「送信して完了」を押すとお礼を出したうえで画面を空に戻します。お礼の件数・時間は、この画面で今回登録した業務だけです。「送信して完了」はこの画面で業務を登録したあとにしか出ないので、前に登録した業務があっても、今回何も登録していなければ「受け付けました」にはなりません。ユーザーIDを入れたときに前回の Gr・役割・勤務形態が入ったら、その欄に前に出ていた「選んでください」は消します。
- 月次アンケートで「なくしたい・自動化したい」業務を挙げた人には、回答のあとに「次は、なくしたい業務の『流れ』を AI と整理してみませんか」と「自動化アイテムを登録する」ボタンが出ます。押すと、その回答（リンクに回答の番号 `m` が付きます）の基本情報と業務名（3-2 で挙げた業務）が入力済みの状態で聞き取りがすぐ始まり、AI はアンケートの答えにひとことふれてから質問します。1件登録すると「次の業務『…』を検討する」が出て、挙げた業務を順に進められます。引き継いだ回答は、業務名の候補と AI の道具 person_history でも直近の回答より優先します。完了ページの控えは、JavaScript が使えないときのフォーム送信（完了ページへ移る）のときだけ残し、一度表示したら消します（ボタンのリンクに回答の番号が付いているので引き継ぎは変わりません）。控えがないとき（完了ページを直接・もう一度開いたとき）は「受け付けました」を出さず、回答フォームへ移ります。完了画面に並べる挙げた業務名は、押せるボタンに見えないよう「・」で並べるだけにしています。画面（JavaScript）からの送信はその場で完了を出すので控えを残さず、前の人の控えが残っていても消します（あとで完了ページを開いても、前の人のリンクは出ません）。月次の業務名（候補のチップ・引き継ぎ）から始めた登録は、その名前を案件に残すので、AI が業務名を言い換えても登録済みとして扱います（引き継ぎの帯・次の業務・候補・業務マップの未登録の業務・始める前の二重登録の警告）。月次アンケートから来たときは、登録済みの業務を読み込んでから次の業務を決めるので、再読み込みしても登録済みの業務をやり直しません。挙げた業務がすべて登録済みなら「月次アンケートで挙げた業務は、すべて登録済みです」と知らせます。引き継ぎの帯の業務名（✓ 登録済み・▶ いま）は押せるボタンに見えないよう、文字だけで並べます。名称は「自動化アイテム登録」です（「自動化を検討」では意味が分かりにくいため。頼めばやってもらえる印象にならないよう「自動化依頼」とはしていません）。画面の説明は「チャットボットとの対話を通じて業務内容・業務フローを整理します。整理された内容は自動化アイテムとして登録され、今後の自動化・業務改善の検討対象となります。」です。
- ユーザーIDが分かっている人は、月次アンケートの直近6か月の進め方（3-3。空でない回答のうち新しいもの）が「自分で取り組みたい」「学びながら改善チームと一緒に取り組みたい」なら、登録前の「スキルを身につけながら、一緒にやってみたい」にチェックが入った状態になります（月次から来たときに限りません。外せます）。6か月より前の回答ではチェックを入れません（人財一覧の「自分で改善したい」と同じ期間）。
- AI は「最初に何をしますか」「それはどこから取りますか」「できたものは誰に渡しますか」のように短く聞きます。答えはチップか一言。答えるたびに右（スマホでは上）の流れ図に手順が増えていき、新しい箱が動いて見えます。一度に複数の手順が入ったとき（一気に書く・写真）も1手順ずつ順に現れ、会話欄にも「手順②〜③を追加」の知らせが出ます。「最初から見る」で育つ様子を再生できます。手順を聞く「次に何をしますか？」は回数に数えず、それ以外の質問が最大6回。手順について聞くときは「①の『…』は何を見て確認しますか？」のように番号と手順名を添え、「ここまで」と言うまで手順を聞き終えません。手順ごとに流れ図の必須要素（だれが・なにを・どこから・どのように・どこへ／だれに・何に使うか）をそろえます。本人の答えから読み取れることは聞き直さず、AI が整理して記録します（受け取り元が複数なら、受け取り元ごとに何をどう受け取るかを対応づけます）。足りない・あいまいな要素があれば、AI が手順の番号と名前を添えて確かめます（例:「①で、PMKからは何で受け取りますか？」。同じ手順の足りない要素は1回にまとめて聞きます）。この確認は質問の回数に数えません。本人が分からないと答えた要素は「分からない」として残して先へ進みます。本人以外（上司・他部署・システム）がやる手順は、図の作業の「だれ」をその人にします。選択肢は青い枠のボタンで、AI の吹き出しとは見た目を分けています。
- 近道として「一気に書く」（1行1手順）と「写真を貼る」（手順書や画面の写真。端末で縮小してから送る。送れる大きさは2MBまでで、超えたら「写真が大きすぎます。もう少し小さい写真にしてください」）があります。AI は読み取れたことをすべて取り込み、足りないことだけ聞きます。
- 交代勤務の人には、この業務をいつやるか（昼勤／夜勤／昼勤・夜勤の両方）を AI が1問だけ聞き、登録前にも選び直せます。案件詳細に出て、改善案件の一覧では夜勤・両方の案件にバッジが付きます。引き継ぎの話が出たら、前の勤務からの引き継ぎを情報のもと、次の勤務への引き継ぎを渡す相手として図に入れます。
- そろったら「この流れで合っていますか？」。「はい」で、頻度・1回の時間（会話から分かっていれば選択済み）・希望（なくしたい／減らしたい／まずは相談したい）と「スキルを身につけながら、一緒にやってみたい」のチェック1つで登録です（見出しは「あと少しです。下の項目を選んで登録してください。」。交代勤務の人は「いつやるか」も選びます）。「はい」は一度押すと止まり、「直したい」を押すと下の欄を閉じて会話に戻ります。戻っても、選んだ頻度・時間・希望は消えません。業務名が決まらないまま流れができたときは、下の欄に業務名の入力欄が出ます。次の業務の聞き取りでは、入力欄の例文を元に戻します。チェックした人には使える技術・学びたい技術のチップが出ます（任意。前に登録した技術が選ばれた状態で出ます。「特になし」は他の技術と同時には選べず、技術の人数・グラフ・教育テーマには数えません）。選択肢は 管理 →「技術の選択肢（自動化アイテム登録）」で、追加・名前の変更・削除・並べ替えができます（設定 `skill_options` に保存。未設定なら既定のリスト。各技術を選んでいる人数も出ます）。名前を変えると、すでに選んでいた人の記録も新しい名前にします。消した技術は次からは選べませんが、すでに選んでいた人の記録は人財一覧に残ります。「特になし」はいつも最後に出て、消せません。チェックしなかった業務は空で保存し（「改善チームに任せたい」という意味にはしません）、案件詳細・案件一覧・案件CSV・AI に渡す内容・人財一覧では「チェックなし」と出します。以前の版で「自動化アイテム登録」から登録した業務（手順あり）の「改善チームに任せたい」は起動時に空にします（手順のない古い様式の業務はそのまま）。
- 聞き取りでは、できるものを聞くときに「誰が何に使いますか？」と渡す相手と使いみちを1問で聞き、使いみちは案件の目的になります（質問の数は増えません）。システム・帳票・できるものの名前は、登録済みの呼び方にそろえます（名寄せ）。
- 登録時に AI が1回まとめて分析し、業務領域・目的・情報のもと・できるもの・利用者・ツール・作業の性質・困りごと・関連業務・ECRS の観点・改善後の流れの案・削減見込み・担当者に確認すべき点を埋めます。AI が埋めた項目は案件詳細に「AI推定」の印が付き、担当者確認で確定します。「まずは相談したい」の案件には改善チーム向けのヒアリング質問が付きます。関連業務は候補の一覧か、AI が道具で見つけた実在の業務だけを残します。
- 関連業務の候補（ルール。案件詳細の「関連しそうな業務」と AI に渡す候補も同じ）は、業務名・アウトプット・目的の語の重なりで選びます。3文字以上の語（日次実績集計表・クレーム など）は重み3、2文字の語（週報・不良 など）は2、長い漢字の語から切り出した2文字どうし（「対応状況」と「稼働状況」の「状況」など）や、ツール・媒体・どの業務にも出る語（Excel・メール・報告・集計・課長・月次 など）は1とし、重みの合計が3以上で、しかも重み2以上の語が1つはあるときだけ関連とみなします。アウトプットが同じ業務と、前の業務・後の業務の名前でつながる業務（どちらから見ても。「月報の作成」と「生産実績の月報作成」のように「の」の有無は問わず、3文字未満の名前ではつなぎません）は、語が重ならなくても候補にします。業務領域・入力元が同じことは順位を上げるだけで、それだけでは候補にしません。
- AI が区分（利用者・入力元・ツール・作業の性質・困りごと）を空で返したとき、一覧にない業務領域を返したとき、AI が応答しないときは、ルールの推定で埋めて「推定」の印を付けます。入力元は取り出し元と判断したものだけ（入力先のシステムや渡し方のメールは入れない）、作業の性質は手順の言葉から（決めつけない）、困りごとは本人の言葉（「何度も」「書き写す」「ミス」など）から区分に分け、元の言葉は困りごとの補足に残します。取り出し元は、「システム」などの語がなくても、モニタ・画面・端末・タブレット・HMI のようなものはシステムの取り出し元として分類し（設備モニタ・モニター → 設備データ、品質の画面 → 品質システム、それ以外は その他）、共有フォルダ・ファイルサーバ（業務マップの区分の「共有フォルダ」の語）から取るファイルは 他のExcel にします。作業の性質の「メール・配布」は、送る・配る・提出・知らせる などの語か、「共有」とメール・チャットがそろったときだけにし、「共有フォルダに保存する」はメール・配布にせず、ファイリングと同じ「台帳更新」にします。業務領域は業務名・目的・手順の語から推定して業務に入れます。渡す相手を「関わる人」にはしません。分析は月間時間を出してから行い、必須項目が足りないときは足りない項目だけを「確認すること」に挙げます。
- AI が推定した「同じ作業をしている人数」は月間時間に掛けず、案件詳細に参考として出します。担当人数は本人の登録か、案件詳細の「業務情報」で改善チームが直したときだけ変わります。
- 氏名は、業務名・聞き取りの記録・AI の文章（要約・ECRS・自動化の案・確認すること・改善後の流れ・一言・ヒアリング質問）とも「担当者」に置き換えてから保存します。
- 完了画面には AI の一言（例: 転記が3回あるので入力を1回にまとめられそうです）が出ます。
- 案件詳細には「手順（聞き取り）」「聞き取りの記録」「改善後の流れ（AI案）」が加わり、流れ図は手順の連鎖で描きます。手順のない古い案件はいままでどおりの図です。
- 案件詳細の「案件管理」の「業務情報」で、業務領域・目的・アウトプット・利用者（区分と補足）・入力元（区分と補足）・頻度・1回の時間・担当人数・前の業務・後の業務・関わる人・情報の受け取り元・使用ツール・作業の性質・困りごと（区分と補足）を直せます。「検討内容」の推定の印を押すと、その項目を直す欄へ移ります（直した項目は推定の印が外れ、氏名は担当者に置き換えます。頻度・1回の時間・担当人数を変えると月間時間を計算し直します）。必須項目が空の欄には「未入力」が付き、担当者確認の「必須項目（…）が未入力です」の案内から、その欄へ飛べます。業務情報を直して保存すると、前回の分析がルールベースなら新しい内容でルールの分析（月間時間を入れた要約・フラグ・確認すること・優先度）をやり直します。AI の分析ならそのまま残して「業務情報を直す前の AI 分析（日時）」の印を付け、「業務情報を直しました。AI 分析を新しくするには「再分析」を押してください」と知らせます（案件CSVの AI要約にも同じ印。再分析で消えます）。業務情報を直した案件は改善チームが手を付けた案件になります（担当区分が自主改善なら人財一覧で「伴走」）。業務領域が空でも、担当者確認のときに AI推定の領域を採用できます。業務領域の「AI推定」と「AI推定に変更する」は、業務領域が空か推定のままのあいだだけ出し、案件管理で業務領域を直したあとや担当者確認のあと（AI推定に変更したときは推定の印も外れます）は、分析をやり直して別の推定が出ても出しません。段階が要件定義より先へ進んだのに標準手順のチェックが追いついていないときは、チェックの更新を促す案内が出ます（自動ではチェックしません）。
- 呼び出しは Responses API（temperature なし）。聞き取りと登録時の分析では AI が道具（tool calling）を使えます。送り方は社内の AI ワークハブ（aiagent_rag_bundle）と同じで、道具の定義は chat 形式（`{"type":"function","function":{...}}`）で持ち、送るときに Responses API の平らな形に直します。`store` は false、`tool_choice` は auto。AI が `function_call` を返したら app.py の中で実行し、`function_call_output`（JSON 文字列、最大 40 行）を積んで呼び直します。往復は最大 10 回、同じ道具を同じ引数で呼び直したら実行せずに「同じ呼び出しです」と差し戻し、2回続いたら道具なしで最終回答をまとめさせます。未知の道具や実行の失敗は `{"error": ...}` として返し、AI に続けさせます。
- 聞き取りの道具: person_history（本人の登録済み業務・月次の答え・勤務形態）、list_known_systems（これまでに出たシステム・帳票名。名寄せ用）、search_similar_tasks（似た業務。他の人の同じ成果物の検出）、check_duplicate（本人の二重登録。ほかの人の同じ業務は二重登録にしない。二重登録でなければ AI は何も言わない）。登録時の分析の道具: search_similar_tasks、duplicate_outputs。道具はすべて app.py の中で SQLite を読むだけで、AI 側から社内 LAN には入りません。
- 管理画面の「保存して接続テスト」は、ふつうの応答に加えて道具の呼び出し（ping）が中継サービスを通るかも確かめ、通らなければその旨を表示します。中継が tools を受け付けない（400 を返す）ときは、その呼び出しを道具なしでやり直して聞き取りを続け、以後そのモデルには道具を渡しません（AI連携の設定を保存し直すと、もう一度試します）。
- 道具の結果は次のターンには持ち越さないので、AI は分かったことを聞き取りの状態のメモ（notes）に残します。本人の履歴と同じ名前の確認は、一度調べたら次のターンでは渡しません。
- 同じ人が同じ業務名をもう一度登録しようとすると、始める前と登録時に警告が出ます。登録時は「別の業務として登録」「やめる」を選べ、前の登録を取り消したいときは改善チームに連絡するよう案内します（API は 409、`force` で続行。AI の聞き取りでも取り消しは勧めません）。登録の取り消しは管理者だけが行います（案件詳細の「登録の取り消し（管理者）」→「この登録を取り消す」。確認のダイアログのあと、AI の聞き取りの記録・流れ図・段階の記録ごと消え、元に戻せません。改善チームが手を付けた案件も取り消せます）。本人は「自動化アイテム登録」の画面から取り消せません（一覧に「取り消す」は出さず、取り消しの API もありません）。別の人が同じ業務名・同じ成果物を登録するのは、統合候補として検出したい状況なので止めません。AI 連携が未設定だと聞き取りは始められません。回答者の画面には「いまは AI の聞き取りを使えないため、登録できません。改善チームに連絡してください。」と出し、「聞き取りを始める」を押せなくします（管理画面の話はしません）。「送信して完了」は業務を新しく送るわけではない（業務は登録したときに保存済み）ので、「送信しました」の知らせは出しません。
- 以前の「改善への関わり方」「部全体について」の節はなくなりました。重複入力や用途不明の帳票は、集まった流れから AI が見つけます。

## 交代勤務への対応

製造部には普通勤務と交代勤務（昼勤・夜勤）があります。アプリは次のように扱います。

- 勤務形態（普通勤務／交代勤務）は初回に本人がプルダウンで選び、人財一覧（`employees` テーブル）に控えます。2回目からはユーザーIDを入れると前回の値が入ります（変わっていたら選び直します）。月次アンケートで選んだGr・役割・勤務形態は「自動化アイテム登録」の回答者にも反映し、業務の登録では控えを古い値で上書きしません（いちばん新しく選んだ値が勝ちます）。月次の回答で書き換えるのは、その月度がその人のいちばん新しい月度（月次の月度・業務を登録した月）以上のときだけで、前の月度にあとから答えても、控えと回答者のいまのGr・役割・勤務形態は変えません（回答そのものには、その月度に選んだ値が残ります。「基本情報」の保存は今月の回答として扱います）。
- 「自動化アイテム登録」では、交代勤務の人にだけ「この業務はいつやりますか（昼勤／夜勤／昼勤・夜勤の両方）」を聞き、案件に残します。AI の分析では、夜勤・両方の業務に「間接部門が不在でも回る対策」を優先して考えさせます。
- 月次集計に「勤務形態別の推移」、ダッシュボードの月次カードに勤務形態ごとの回答者数、人財一覧に勤務形態の列と自主改善希望者の内訳を出します。勉強会や記入会を昼夜どちらにも開く計画に使えます。
- 推計の係数（1か月のシフト数）は `app.py` の `SHIFTS_PER_MONTH`（20）で、普通勤務・交代勤務とも同じです（勤務形態ごとに変えるときは `shifts_per_month` を直します）。頻度の「毎日」は画面では「毎日（出勤のたび）」と表示します。
- 月末の夜勤で 0 時をまたいで回答しても、前月度の回答として受け付けます（当月と前月度は受付可能）。
- 24 時間使うには、サーバーの PC をスリープさせず、waitress をシステム起動時に動かす（タスクスケジューラの「システム起動時」か NSSM でサービス化）、Windows Update の再起動時間帯を夜勤の作業と重ねない、といった運用が要ります。

## 月間時間の算出ルール（企画書・設計書.md の設計書「10. 集計・活用の流れ」）

月間時間（分）＝ 頻度係数 × 1回あたり時間 × 担当人数

| 頻度 | 係数 | | 1回あたり時間 | 換算 |
| --- | --- | --- | --- | --- |
| 毎日 | 20 | | 15分未満 | 10分 |
| 週に数回 | 10 | | 15〜30分 | 22分 |
| 毎週 | 4 | | 30分〜1時間 | 45分 |
| 毎月 | 1 | | 1〜2時間 | 90分 |
| 四半期・年次 | 0.3 | | 2時間以上 | 150分（個別確認） |
| 不定期 | 1（月1回として計算） | | | |

不定期は画面で「不定期（月1回として計算）」と表示します。担当人数は本人か改善チームが入れた値だけを使い、AI が推定した人数は掛けません。起動時に、既存の不定期の案件の月間時間を計算し直し、以前に AI の推定人数を掛けていた案件（担当者確認の前のもの）は担当人数を1に戻して推定を参考として残します。

月次アンケートの推計月間時間 ＝ 1シフトあたり合計時間の換算値（各区分の中央値: 15分未満＝0.125、15〜30分＝0.375、30〜45分＝0.625、45分〜1時間＝0.875、1〜1.5時間＝1.25、1.5〜2時間＝1.75、2〜3時間＝2.5、3〜4時間＝3.5、4〜6時間＝5、6時間以上＝7 時間。以前の区分の回答は 0／0.25／0.75／1.5／3／5 時間で換算）× 20（1か月の出勤日数の目安）。係数は `app.py` の「選択肢・係数」セクション（`MONTHLY_HOURS_OPTIONS`、`SHIFTS_PER_MONTH`）で変更できます。

## 分析不足領域の判定

業務領域ごとに「登録件数」と「必須項目（目的・アウトプット・利用者・入力元・頻度・時間）の充足率」「担当者確認率」から判定します。目的が「不明」、アウトプットが「不明」「分からない」、利用者が「分からない」だけのときは、その項目は埋まっていない扱いにします（案件詳細では「不明」の印、担当者確認の案内は「未入力か『不明』」）。次のアクション提案の「調査」は、登録が少ない領域（3件未満）と、必須項目が足りない領域を分けて書きます。「ECRS 排除」は廃止・統合候補（完了を除く）の件数で、リンク先の一覧と同じ数になります。「ECRS 結合」は業務マップの重複・つながりへ移ります。「回答促進」にはリンクを付けません。デモデータを投入・削除すると、前のデータで作った AI の提案は消します。ダッシュボードの回答率は上の指標だけに出し（月次のカードには重ねない）、活動状況へのリンクに進行中の件数は重ねません。

| 分析状態 | 業務把握 | 条件 |
| --- | --- | --- |
| 分析済み | 十分 | 8件以上かつ充足率80%以上（確認率50%未満なら追加調査に下げる） |
| 追加調査 | 一部 | 3件以上かつ充足率50%以上 |
| 情報不足 | 不十分 | 1件以上 |
| 未分析 | 不明 | 0件 |

しきい値は `app.py` の `ANALYSIS_LEVELS` で変更できます。

## 画面の動き

触って気持ちよく使えるように、控えめな動きを入れています（OS の「視差効果を減らす」「アニメーションを減らす」設定のときは止まります）。

- ページを移るとふわっと切り替わり、ヘッダーのいまのページの印が次のタブへ滑って移ります（Chrome・Edge の新しい版。対応していないブラウザでは普通に切り替わります）。
- スクロールして見えてきたカードは下から現れます。数字は 0 から数え上がり、グラフは伸びて描かれます。
- ボタンは押した所から波紋が広がり、送信中はくるくる回る印が出て二度押しを防ぎます。
- 「保存しました」などのお知らせは右上に出て数秒で消えます（触れている間は止まります）。注意・エラーは本文に残ります。
- 月次アンケートは、必須の設問に答え終わると送信ボタンが光ります。回答・登録が終わると紙吹雪が舞います。
- 流れ図は描き終わるまで光の流れる下地を出し、「最大表示」はふわっと広がります。

## 運用上の注意

- 社内ネットワーク向けの最小構成です。CSRF対策・HTTPS はありません。外部公開する場合は追加してください。
- Bootstrap、Chart.js、Mermaid、Web フォント（Inter・Noto Sans JP）は CDN から読み込んでいます。インターネットに出られない環境では `app.py` の STATIC に置き、テンプレートの CDN 参照を書き換えてください（フォントが読めない場合は端末の標準書体で表示されます）。
- 回答は記名式です。案内文のとおり「改善目的に限定し、評価には使わない」ことを周知してください。
- 業務領域の初期値（8領域）は仮説です。業務体系（大分類・中分類）が固まったら「管理」で更新してください。
